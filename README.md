# Каталог книг — фронтенд (тестовое задание)

Фронтенд для API каталога книг (спека в `book.yaml`). Vue 3 + Vite + TypeScript + PrimeVue + Vitest.

## Запуск

```bash
npm install
npm run dev       # http://localhost:5173
npm test          # unit-тесты
npm run build     # production-сборка + проверка типов
```

## Демо-режим

Проект работает со **встроенным мок-бэкендом** — реальный бэкенд не нужен, всё запускается сразу.
Мок повторяет все эндпоинты `book.yaml` 1:1
(форматы ответов, пагинация, ошибки `{ success:false, errors:[{field,message}] }`, статусы 401/404/422).

**Войти как пользователь** — на странице входа любые логин и пароль (в демо-режиме);
роль всегда `user`. **Гость** — режим без входа; можно просто закрыть форму входа
(кнопка «Смотреть каталог как гость»).

## Ограничения и осознанные упрощения

- **Подписка на автора** — «плюс» из задания. В `book.yaml` нет ни одного endpoint`а для
  подписок и SMS (smspilot), поэтому на клиенте это UI-заглушка: сохранение в `localStorage`,
  поле номера телефона, статус «вы подписаны».
- **CRUD авторов** в UI не делаем (задание — про книги); авторы только просматриваются.
  Выбор авторов при создании/правке книги — из существующего списка.
- **Обложка**: обязательна только при создании книги; при правке менять необязательно.

## Структура

```
src/
  shared/               переиспользуемое между модулями
    api/          мок-бэкенд (mock/), клиент (index.ts)
    types.ts      контракт API (ApiClient, Book/Author и т.д.)
    utils/        валидация форм, маски ввода
    components/   AppHeader, BookCard, BookModal, EmptyState
    composables/  useAuth, useAuthorsOptions
  modules/              модули = страницы; друг с другом не общаются
    catalog/      Каталог: CatalogView, useCatalog, routes
    author/       Страница автора: AuthorView, SubscribeDialog, useSubscriptions, routes
    top-authors/  ТОП-10 авторов: TopAuthorsView, routes
    login/        Вход: LoginView, routes
    not-found/    404: NotFoundView, routes
```

Каждый модуль экспортирует свои роуты (`routes.ts`), корневой `src/router.ts` их собирает.

**Правило модульности**: страницы-модули не импортируют друг друга — всё общее живёт в `shared/`.
